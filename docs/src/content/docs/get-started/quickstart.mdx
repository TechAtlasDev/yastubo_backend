# Quickstart: Tu primera póliza en 5 minutos

En esta guía, aprenderás a interactuar con la API de Yastubo para completar el flujo principal de negocio: desde la autenticación hasta la emisión de una póliza activa.

## Requisitos Previos

1.  Servidor local corriendo en `http://localhost:8000`.
2.  Haber ejecutado `scripts/backend_setup.py` (esto crea el usuario administrador por defecto).
3.  Un cliente REST (cURL, Postman, Insomnia) o usar la Swagger UI en `/docs`.

---

## Paso 1: Autenticación

Primero, necesitamos obtener un Token de Acceso (JWT). Por defecto, el sistema viene con un usuario `admin@yastubo.com` (password: `admin1234`).

```bash
curl -X POST http://localhost:8000/api/v1/auth/login \
     -H "Content-Type: application/json" \
     -d '{"email": "admin@yastubo.com", "password": "admin1234"}'
```

**Respuesta:** Guarda el `access_token` para los siguientes pasos.

---

## Paso 2: Crear un Cliente

Antes de emitir una póliza, necesitamos registrar a la persona que será el titular (Suscriptor).

```bash
curl -X POST http://localhost:8000/api/v1/emission/clients \
     -H "Authorization: Bearer TU_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{
       "first_name": "Juan",
       "last_name": "Pérez",
       "email": "juan.perez@example.com",
       "phone": "+34600000000",
       "birth_date": "1990-01-01",
       "nationality": "ES",
       "country_of_residence": "ES",
       "document_type": "DNI",
       "document_number": "12345678Z"
     }'
```

---

## Paso 3: Elegir un Plan y Emitir la Póliza

Obtén la lista de planes disponibles y usa el ID del plan deseado junto con el `client_id` obtenido en el paso anterior.

```bash
# 1. Listar planes para obtener un PLAN_ID
curl http://localhost:8000/api/v1/plans/

# 2. Emitir Póliza (Estado Inicial: DRAFT)
curl -X POST http://localhost:8000/api/v1/emission/policies \
     -H "Authorization: Bearer TU_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{
       "client_id": "ID_DEL_CLIENTE",
       "plan_id": "ID_DEL_PLAN"
     }'
```

---

## Paso 4: Transición a Activa (Simulación de Pago)

Una póliza recién creada está en estado `DRAFT`. Para activarla, normalmente se procesa un pago a través de Stripe. En este Quickstart, forzaremos la transición de estado.

```bash
curl -X POST http://localhost:8000/api/v1/emission/policies/ID_DE_LA_POLIZA/transition \
     -H "Authorization: Bearer TU_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"target_status": "ACTIVE"}'
```

---

## Verificación: Generar Certificado PDF

Una vez activa, puedes descargar el certificado legal de la póliza.

```bash
curl http://localhost:8000/api/v1/emission/policies/ID_DE_LA_POLIZA/pdf \
     -H "Authorization: Bearer TU_TOKEN" \
     --output certificado_yastubo.pdf
```

## Deep Dive: El Ciclo de Vida de la Póliza

El motor de emisión de Yastubo utiliza una **Máquina de Estados Inmutable**. Esto significa que no puedes saltarte pasos sin la validación adecuada (ej. no puedes pasar de `DRAFT` a `ACTIVE` sin un método de pago válido en el flujo real).

### Lógica de Transición
Las transiciones están protegidas por lógica de negocio que verifica:
1.  **Edad del Beneficiario:** ¿Cumple con los límites del plan?
2.  **Estado de Pago:** ¿Se ha confirmado el webhook de Stripe?
3.  **Audit Trail:** Se genera una entrada en la tabla de auditoría con el motivo del cambio.

<Aside type="tip">
  En producción, el cambio a `ACTIVE` ocurre automáticamente cuando recibimos el evento `checkout.session.completed` de Stripe.
</Aside>

> [FLOW: El Usuario se autentica y obtiene un JWT. Envía los datos del Cliente al Módulo de Emisión. Con el Client ID, solicita la creación de una Póliza vinculada a un Plan.
