Yastubo Backend utiliza un **Bus de Eventos Asíncrono** diseñado para disparar flujos de trabajo en n8n de forma transparente y sin penalizar el rendimiento del core (patrón *fire-and-forget*).

## Arquitectura de Integración

El flujo de datos sigue un modelo de "Gritar y Olvidar":

**Backend (Service)** ➔ `notify_n8n()` ➔ `asyncio.create_task` ➔ **n8n Webhook** ➔ `[Zoho/WhatsApp/Sheets]`

---

## ⚙️ Configuración del Entorno

Para activar el bus de eventos, debes configurar las URLs de tus webhooks de n8n en el archivo `.env`. El sistema soporta enrutamiento específico por tipo de negocio.

<Tabs>
  <TabItem label="Configuración General">
    ```bash
    # Fallback para todos los eventos no específicos
    N8N_WEBHOOK_URL="https://n8n.tu-dominio.com/webhook/general"
    ```
  </TabItem>
  <TabItem label="Configuración por Módulo">
    ```bash
    # Enrutamiento dinámico según el tipo de evento
    N8N_WEBHOOK_LEADS="https://n8n.tu-dominio.com/webhook/leads"
    N8N_WEBHOOK_PAYMENTS="https://n8n.tu-dominio.com/webhook/payments"
    N8N_WEBHOOK_POLICIES="https://n8n.tu-dominio.com/webhook/policies"
    ```
  </TabItem>
</Tabs>

## 📡 Eventos Core Implementados

Actualmente, el sistema emite automáticamente los siguientes eventos para alimentar tu máquina de ventas:

| Evento | Módulo | Cuándo se dispara | Payload Clave |
| :--- | :--- | :--- | :--- |
| `LEAD_CREATED` | CRM | Registro de nuevo prospecto. | `lead_id`, `email`, `source` |
| `CLIENT_REGISTERED` | Emisión | Registro de cliente formal. | `client_id`, `email`, `company_id` |
| `POLICY_ISSUED` | Emisión | Póliza creada inicialmente. | `policy_number`, `amount` |
| `POLICY_STATUS_CHANGED`| Emisión | Cambio de estado (ej. Active). | `old_status`, `new_status` |
| `SUBSCRIPTION_ACTIVATED`| Pagos | Pago inicial de suscripción OK. | `subscription_id`, `amount` |
| `PAYMENT_FAILED` | Pagos | Intento de cobro fallido. | `error`, `attempt_count` |
| `PAYMENT_RETRY_SCHEDULED`| Pagos | Reintento automático programado. | `scheduled_at`, `amount` |
| `COMMENT_RECEIVED` | AI / Chat | Mensaje entrante del usuario. | `message`, `channel` |
| `AGENT_HANDOFF_REQUIRED`| AI | El bot detecta necesidad humana. | `reason`, `last_bot_response` |
| `CLAIM_OPENED` | Siniestros | Reporte de un nuevo siniestro. | `claim_id`, `claim_type` |
| `CLAIM_STATUS_CHANGED` | Siniestros | Cambio en la gestión del caso. | `old_status`, `new_status` |

## 🛠️ Cómo agregar un nuevo Evento

Cualquier desarrollador puede extender la capacidad de automatización de Yastubo siguiendo nuestra guía de ingeniería. El Bus de Eventos está diseñado para ser desacoplado:

<Steps>
1.  **Identificar el punto de negocio:** Localiza el `service.py` donde ocurre la acción.
2.  **Importar el dispatcher:** `from app.core.events import notify_n8n`
3.  **Llamar a la función:** Pasa el nombre del evento y un diccionario plano con la data.
4.  **Configurar n8n:** Crea tu workflow y listo.
</Steps>

:::tip[¡Potencia Ilimitada!]
Con esta arquitectura, puedes implementar las 18 automatizaciones de nuestro Roadmap (Zoho, WhatsApp, TikTok, Meta) en cuestión de horas. Consulta la sección de [Guías de Desarrollo](../guides/index.md) para más detalles sobre cómo crear módulos que emitan eventos personalizados.
:::

## 🛡️ Robustez y Límites

-   **Timeout Estricto:** El backend espera máximo **3 segundos** por n8n. Si n8n no responde, el backend cancela la petición para proteger la salud de la API.
-   **No Bloqueante:** Las llamadas se ejecutan en una tarea de `asyncio` separada. Un fallo en n8n **nunca** hará que falle una transacción en Yastubo.
-   **Logging:** Los fallos de conexión (HTTP 4xx/5xx) se registran con el tag `[n8n]` en los logs del sistema para facilitar el debugging.
